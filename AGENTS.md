# AGENTS.md — rsmart R Package

## Project Overview

`rsmart` is an R package for planning and analyzing Sequential Multiple
Assignment Randomized Trials (SMARTs) with normal, binary, and
time-to-event endpoints. It implements the IPWE, AIPWE, and IAIPWE
estimators from Manschot, Laber, and Davidian (2023), which includes
implementation for Wu, Wang, and Wahed (2023) and Zhang, Tsiatis, Laber,
and Davidian (2013).

## Key Source Files (R/)

- **iaipwe.R** — Main entry point: the
  [`iaipwe()`](https://msdllcpapers.github.io/rsmart/reference/iaipwe.md)
  function implements the IAIPWE estimator for K-stage SMARTs with up to
  2 treatment options at each stage.
- **estimate_all_values.R** — Estimates values for all treatment
  regimes.
- **gen_no_trt_resp.R** — Generates treatment and response regime lists
  ([`gen_no_trt_resp()`](https://msdllcpapers.github.io/rsmart/reference/gen_no_trt_resp.md),
  `regimelist_no_trt_resp()`).
- **q_step.R** / **pi_step.R** — Q-learning and propensity score model
  fitting steps.
- **ee_value.R**, **ee_value_ipw.R** — Estimating equations for value
  estimation (augmented and IPW).
- **ee_value_derivatives.R**, **ee_value_derivatives_ipw.R** —
  Derivatives of estimating equations.
- **ee_beta.R**, **ee_nu.R**, **ee_pi.R** — Estimating equations for
  model parameters.
- **An.R**, **Bn.R** — Computation of A_n and B_n matrices used in
  variance estimation.
- **nu.R**, **kappa.R** — Helper functions for nu and kappa terms.
- **value_terms.R** — Intermediate value computation terms.
- **get_bounds.R**, **get_sample_size.R** — Confidence bounds and sample
  size calculations.
- **data.R** — roxygen2 documentation for the `pcsttrial` dataset.

## Data

- **pcsttrial** — A simulated dataset (284 observations, 14 variables)
  mimicking the Pain Coping Skills Training trial. Variables include
  baseline covariates (`pctchange`, `height`, `weight`, `comorbidity`,
  `painmed`, `chemo`), stage-2 covariates (`pctchangek2`, `adherence`),
  treatment assignments (`a1`, `a2`), a response indicator (`r2`), and
  timing variables (`study_day_enroll`, `study_day_rerand`,
  `study_day_outcome`).

## Boundaries

The following guidelines define what AI agents **should** and **should
not** do when editing this package.

### Do

- Follow existing coding conventions (snake_case, roxygen2 markdown,
  `package::function()` prefixing).
- Add or update roxygen2 documentation when modifying exported
  functions.
- Run `devtools::document()` after changing roxygen2 headers or
  `@importFrom` directives.
- Run `devtools::check()` after making changes and fix any introduced
  errors, warnings, or notes.
- Write or update `testthat` tests for any new or changed functionality.
- Keep changes minimal and focused — prefer small, reviewable edits.
- Preserve the existing package structure and file organization.
- Update `AGENTS.md` if structural changes are made (new exported
  functions, new files, new dependencies).

### Do Not

- **Do not** edit auto-generated files (`man/`, `NAMESPACE`) directly;
  use `devtools::document()` instead.
- **Do not** change the core statistical methodology (estimating
  equations, variance formulas, value estimation logic) without explicit
  instruction. These implement published methods from peer-reviewed
  papers.
- **Do not** add new package dependencies (Imports or Suggests in
  `DESCRIPTION`) without explicit approval.
- **Do not** modify or delete the `pcsttrial` dataset or its raw data
  without explicit instruction.
- **Do not** change function signatures of exported functions (argument
  names, order, or defaults) without explicit instruction, as this is a
  breaking change.
- **Do not** remove existing tests or lower test coverage.
- **Do not** commit credentials, patient data, or any sensitive
  information.
- **Do not** change the license or authorship metadata in `DESCRIPTION`.
